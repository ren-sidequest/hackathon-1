## 0. API4已接入上线：现按同版证据收口

当前以GitHub main `b5d0568`及 [API4整合说明](https://github.com/ren-sidequest/hackathon-1/blob/b5d0568c71fd51f4f39f3eb506654861c1b59695/docs/FRONTEND_API4_INTEGRATION.md) 为准；早期源码ZIP保留历史，包内旧UI不覆盖现有工作。以下为已接入的合同来源，不是待开发字段。

| 要接的内容 | 已冻结的来源／规则 |
|---|---|
| schema／类型 | `schemaVersion: "4.0"`；`app/shared/api4-types.ts`；`scripts/frontend-types-v4.py` |
| 人物列表 | `GET /api/demo/comparison` → `data.candidates` |
| 本人完整数据 | `GET /api/demo?candidateId=…` → `data` |
| 当前申请评估 | `data.assessment.application_review`；`application.baseline` 只是不可变初始记录，不替代后来的人工修订 |
| JD 与本人对照 | `data.job.jd.source/requirements`；`data.application.jdAlignment`，每人 19 行，可多个证据状态并存 |
| 评审完成／核心证据完整 | comparison `applicationsReviewed`／`candidatesWithCompleteCoreEvidence`；初始分别为 4／2，动态读取 |
| 分项与综合 | `score.skills[]`、`score.overallPercentage`；`accruedScore`、`coveragePercent` 是另外两件事；NE 不作 0 |
| 追问建议 | `data.gapSuggestions` 只针对当前 `application_review`，不是任务 V1/V2 的通用诊断；HR 显式确认目标 |
| 来源与 PDF | `application.sources[].provenance`；`downloadUrl` 是服务相对路径，公网须拼 `/gateway`，不要用裸 `/api/…` |
| 引文 | 对原文做 JS `slice(start,end)`，UTF-16、end exclusive；保留 person／snapshot／fingerprint／sourceId／location |
| 模式与写权限 | 页面显示实际规则模拟；当前部署公开共享业务读写，无登录探测。401保留草稿与原请求并提示核对共享服务，不引导登录 |
| 旧版本 | 旧 ID 或显式旧 schema 返回 409 `SCHEMA_MISMATCH`；旧草稿不可自动换绑新人 |

请求绑定当前 schema、session、candidate、job、dataset 与对应版本；以实时 GET 为准，别复用示例中的随机 sessionId。JSON schema 拒绝多余字段，字段级错误路径本轮未添加。API4 初始成绩是内容快照而非 UI 常量：不得硬编码 Amy／Ann 的数字或为 David／Jamie 填零。

## 1. 开发顺序与责任

以下保留早期实施阶段分解，不是本次待开发任务；当前API4已上线，执行结果见上节。

| 阶段 | 小傅可以先做 | 依赖后端 |
|---|---|---|
| G0／G1a | 核对 API3 基线；现有页面信息架构、英文、空状态、读写提示与样式 | 新身份／来源／JD 字段草案和示例 |
| G1b／G2 | 接四人、材料、逐项评分、JD 对照、比较与任务入口 | 冻结合同、生成类型、真实初始响应 |
| G3 | 四人切换、两目标双端流程、异常、桌面／手机测试 | 相容的隔离后端，不用现网写入验收 |
| G4 | 交接截图、短录屏、演示步骤、未完成项 | 发布时另行确认的整体版本 |

你拥有 HR／Candidate 页面、共享 API4 UI／客户端／控制器（历史API3独立保留）与相应浏览器测试。后端拥有 schema／fixtures／内容／评分引擎／存储／OpenAPI 和共享**生成类型**。需要字段先提合同，不改服务端评分规则，不再维护一套前端人物／分数／rubric。双方不要同时写同一工作副本。

不在此清单新增付费、正式登录、多租户、任意 CV 上传／OCR、动态出题或无限补交。当前连通页维持真实 API；显式模拟预览可以保留，但断网不自动转假数据并显示成功。
