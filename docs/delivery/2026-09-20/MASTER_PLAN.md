## 5. 如何评估：标准、分数与可展示实例

### 5.1 十项核心标准

| ID | 技能 | 观察内容 |
|---|---|---|
| S1 | SQL | 输入粒度、聚合与适用连接逻辑，重复风险 |
| S2 | SQL | 时间窗、期间／分组比较、代码与解释的可复核性 |
| S3 | SQL | 检查方法、预期检查结果、重复／空值／零分母等适用边界 |
| D1 | Data Analysis | 指标、分子分母、单位与正确计算 |
| D2 | Data Analysis | 有意义的期间／分组比较，权重与重叠数据 |
| D3 | Data Analysis | 复核过程、来源与限制，清楚表述计算依据 |
| B1 | Business Problem Solving | 业务问题与需要支持的实际决策 |
| B2 | Business Problem Solving | 观察、假设和因果的区分 |
| B3 | Business Problem Solving | 有区分力的数据请求及不同结果的意义 |
| B4 | Business Problem Solving | 合理行动顺序、理由和验证方式 |

每项 10 分；SQL／DA／BPS 为 30／30／40。**这是团队预先确定的核心能力 demo rubric，不是 JD 提供的权重，也不是覆盖全部招聘条件的模型。** 不为某人的背景调整权重，不把高级算法、学校名气或文本长度当加分项。

### 5.2 Mark、NE、待评与计算

| 状态 | 意义 |
|---|---|
| 4 | 可观察要求充分满足，相关解释和边界充分 |
| 3 | 主要满足，指出具体非关键缺口 |
| 2 | 部分满足，有影响判断的明显缺口 |
| 1 | 有相关尝试，但具体支持较弱 |
| 0 | 已观察到明确问题，有原文依据 |
| NE | 材料不足以判断，记录检查范围和缺什么 |
| Pending／null | 尚未完成判断，不等于 NE 或 0 |

```text
单项贡献 = Mark / 4 × 10
完整技能百分比 = 该技能贡献之和 / 技能满分 × 100
完整核心综合百分比 = 十项贡献之和（满分 100）
证据覆盖率 = 数值 Mark 项目数 / 10 × 100（整组已审后）
```

- 有 NE：综合为 null；完整技能仍可展示百分比；不把余项重新放大到 100%。
- 未完成整组评审：显示 Not reviewed / Assessment pending；当前合同的覆盖率可为空，另列已审项数。
- NE 是已审后缺证；`assessmentComplete` 与 `score.complete` 不等价。四人已审但两人缺证时显示“4 applications reviewed；2 with complete core evidence”，不是“只评完两人”。
- 原值计算，最终一位小数；累计支持分、证据覆盖率、完整匹配百分比名称分开。
- 英文主名称建议 `Core analytical evidence match`，副说明 `SQL, Data Analysis and Business Problem Solving evidence for this role`；邻近显示完整 JD 要求状态。
- 不是录用成功率、实际能力百分位或留任概率；没有自动通过线。

### 5.3 逐项评分锚点：让 4、2、0 有具体含义

以下为本轮岗位的设计基准，配合原文使用。3 分表示主要要求已满足但仍缺一项非关键说明；1 分表示有相关尝试但尚未达到 2 分的具体支持。若作品含实质矛盾，应在理由中说明它如何影响本项分数，不靠文本长度或关键词计数。

| 项目 | 4 分的充分支持 | 2 分的部分支持 | 0 分的明确问题示例 |
|---|---|---|---|
| S1 查询逻辑 | 粒度明确，聚合／连接与所问问题一致，并核对重复风险 | 基本聚合可读，但粒度或连接的计数影响说明不足 | 可见的重复连接使关键计数错误，却将其作为正确结果 |
| S2 时间比较 | 时间窗、分组和比较对象清楚，代码与解释一致，可按过程复核 | 有查询或期间比较，但过滤条件／边界解释不完整 | 把不同期间或不相关分组混作同一比较对象 |
| S3 校验 | 有可操作的结果检查和适用边界，说明预期检查结果 | 提到空值／重复等检查，但方法或预期结果不充分 | 明知校验不通过仍宣称结果正确，或校验逻辑明显无效 |
| D1 指标 | 指标定义、分母、单位、期间和计算都清楚且一致 | 主要计算可用，但某项定义或单位解释不足 | 使用错误分母形成核心结论，且没有识别／修正 |
| D2 比较 | 总量和相关分组比较合理，注意权重及重叠总体 | 能看到一个有用变化，但缺少相应分组或基准 | 把重叠资源相加，或直接平均比例后作关键结论 |
| D3 复核与限制 | 给出可重复的计算依据，明确缺失数据与适用范围 | 有过程或限制说明，但另一部分较弱 | 使用材料中不存在的数据并当成已观测事实 |
| B1 业务问题 | 明确业务决策、需要回答的问题和现实约束 | 能描述下降现象，但与业务决策连接不充分 | 明确回答了无关问题，并将其当成当前决策依据 |
| B2 因果区分 | 事实／假设分开，考虑合理替代解释及推断边界 | 有假设意识，但个别陈述仍把关联说成原因 | 无对应证据，却明确断言唯一原因已经证实 |
| B3 补证计划 | 具体数据、比较方法及不同结果如何区分假设都清楚 | 给出具体数据请求，但未解释怎样判别假设 | 所提方法逻辑循环或与待判断假设无关，却声称可验证 |
| B4 行动 | 优先级、理由、可执行步骤与验证指标匹配公司约束 | 有相关行动，但顺序、验证指标或停止条件不足 | 行动与自己确认的关键证据明显矛盾且无解释 |

**NE 单独处理：**没有相关内容，或材料范围不足以评该项，显示 NE。未运行 SQL 不自动是 0；没有 SQL 材料也不借用其他人的查询得分。0 分必须能指出已经观察到的具体问题。


### 5.4 从材料到判断的工作过程

先锁定标准 → 逐人阅读原文 → 对十项记录满足点／问题／缺口 → 标 Mark 或 NE → 校验来源 → 复算 → 复核分歧 → 发布有来源和实际标注方式的基准版本。

每项至少包含 criterionId、mark、support、gaps、rationale、uncertainty、nextStep、checkedSourceIds、sourceRefs。数值 0 也要引用；NE 可无正向引文，但须交代已检查范围。引用绑定人物、材料快照、指纹、sourceId、location、UTF-16 区间。PDF 来源另带页号／节标题供人理解；机器定位仍按实际提取文本校验。

AI agent 编写和交叉检查的基准显示 `AI-authored demo assessment · Human calibration pending`；人实际确认后再显示相应人工评审记录。内部多角色审阅不等于外部专家或真人已校准。团队可独立抽核几项并记录分歧；尚未进行时如实保留 pending，不虚构签名。
